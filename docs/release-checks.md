## 已复现问题

### R1 / P1：Base64 文件写入会破坏源文件或旧结果

- 位置：`src-tauri/src/lib.rs:157`、`:175`。
- 从现有函数提取后台闭包，在临时目录执行相同逻辑：编码或解码的输入/输出选为同一路径，均返回成功，但文件变成 **0 字节**。
- 非法 Base64 输入 `!!!!`，目标文件原有内容时，解码报错，但目标已经被截断为 0 字节。
- 原因：先 `File::open`，随后直接 `File::create(output_path)`，未识别同一文件，也没有事务式写入。
- 建议：先验证输入/输出不是同一文件（覆盖路径别名、大小写、符号链接/硬链接边界），写临时文件、确认完成后再替换目标；失败保留旧文件并清理临时结果。
- 复验：同路径及别名保护、正常往返、空文件、非法内容、大文件、取消、目标不可写；失败前后源文件/已有目标逐字节不变。

### R2 / P1：文档预览保留可执行 HTML

- 位置：`src/views/DocumentMarkdownView.vue:68`、`:102`；`src-tauri/tauri.conf.json:23`。
- 使用临时 DOCX，其正文是一个带无害 DOM 标记事件属性的 HTML 片段；实际 `.venv` runner 转换成功，Markdown 保留原片段，`marked.parse` 后仍包含 `onerror`。
- 页面把此结果直接交给 `v-html`，没有 HTML 净化；当前 CSP 为 null。此为代码与真实转换链确认的脚本注入风险，未在真实桌面环境执行攻击、读取私人文件或发起外传。
- 配套权限检查发现：文件 MD5 / Base64 和文档自定义 Rust Command 直接使用字符串路径，未检查 Dialog/FS 的授权 scope。FS 插件权限不会自动约束直接 `std::fs` 调用；脚本注入可能扩大影响，应同时收紧这个边界。
- 建议：净化 HTML，只允许必要 Markdown 标签；限制事件属性、脚本 URL、嵌入资源和远程图片/导航；评估兼容 CodeMirror/Worker 的 CSP。自定义文件 Command 验证用户选择的输入和输出授权。
- 复验：标题/表格/列表/代码保持正常，HTML 事件和脚本 URL 被移除；远程内容不自动加载，不发生页面跳转；超出授权文件路径被拒绝。

### R3 / P1：文档保存可能写入另一份文档的内容

- 位置：`src/views/DocumentMarkdownView.vue:148`。
- 对原组件脚本执行隔离异步模拟：从 A 打开保存对话框，期间选中 B；对话框返回 `A.md` 后，实际写入 **B markdown**。
- 原因：默认名称取自等待前的 activeDocument，写入内容取自等待后的 activeDocument。
- 建议：保存开始时捕获文档标识、名称和 Markdown 快照；成功/失败提示对应任务，异常需捕获。复制、文件 Base64 的对话框等待边界也应一并检查。
- 复验：等待期间切换、删除、清除、重新转换，均不导致错文档保存；取消与写入错误有明确提示。

### R4 / P1：Base64 编码最后的缓冲写入错误可能被忽略

- 位置：`src-tauri/src/lib.rs:165`。
- 当前 base64 crate 的 `EncoderWriter::finish()` 返回内部 `BufWriter`；函数直接丢弃它。
- 使用会在真正写入时报错的模拟 writer：`io::copy` 和 encoder `finish()` 都成功，最终 drop 才尝试写入，错误被丢弃。存在磁盘空间不足等情况下“成功但结果未完整写入”的风险。
- 建议：显式检查最终缓冲 `flush` / `into_inner`，需要时检查文件同步，再提交最终目标。与 R1 的安全写入流程一起修复。
- 说明：相同模拟下解码的 `io::copy` **确实返回了写入错误**，本轮不把该解码分支误报为同样的假成功。

### R5 / P2：批量文档转换会跳过项目且完成统计不准确

- 位置：`src/views/DocumentMarkdownView.vue:125`、`:160`；选择、删除、清除按钮未受 converting 限制。
- 原组件脚本异步模拟：队列 A/B/C 开始转换 A，期间删除 A；下一次实际调用是 C，B 被跳过，界面仍显示“已转换 2 个文档”。
- 另一个选择问题：当前选中 B，删除它前面的 A 后，activeIndex 未随移除位置调整，选中内容变成 C。
- 建议：固定本次任务快照/使用稳定路径标识，或转换期间禁用队列修改；按本次任务实际成功/失败数统计，删除非当前项时保持原选择。

### R6 / P2：MD5 结果会与当前输入不一致

- 位置：`src/views/Md5View.vue:34`、`:78`、`:89`。
- 原组件脚本模拟：计算 `abc` 后把输入改为 `abcd`，仍显示且允许复制 `abc` 的摘要。
- 原因：未监听输入、文件或模式变化清理结果，异步请求也没有过期结果保护。文件大任务没有接回已有进度事件，按钮未提供运行中状态。
- 建议：将输入与结果任务绑定，变化时失效旧结果，重复请求和清除后迟到响应不得回写；补忙碌状态及文件进度。

### R7 / P2：Base64 文本编码大输入失败，解码可能静默损失内容

- 位置：`src/views/Base64View.vue:72`、`:82`。
- 原脚本在当前 Node 运行时处理 100 万 ASCII 字符时，因展开为函数实参超过上限而失败；没有明确大小限制或分块处理。
- `/w==` 是 Base64，但其解码字节不是合法 UTF-8；当前 TextDecoder 默认替换为 `�`，仍提示“解码完成”。
- 建议：分块或字节流安全编码，给出输入上限；文本解码使用严格 UTF-8，二进制内容提示改用文件模式。失败时清除旧结果/成功提示。
